The package was vendored in-tree (rather than declared as a go.mod
dependency) to keep the lark-bridge module self-contained for the
Claude Code backend. All upstream files (code + tests) were copied
verbatim; only `examples/`, `integration_test.go`, the standalone
`go.mod`, and project-level docs (`README.md` / `PLAN.md` / `AGENTS.md`)
were dropped as library-irrelevant.

Local divergence from the pinned commit (track here so upstream merges do not
silently revert them):
- `client.go` + `stream.go`: `buildCommand` now wires `cmdutil.ApplyGroupCancel`
  (process-group SIGKILL + WaitDelay) instead of a bare `Setpgid`, and the
  manual kill goroutine in stream.go was removed (ApplyGroupCancel's Cancel
  closure supersedes it). Fixes a `cmd.Wait()` hang when a tool grandchild
  escapes the SIGKILL but keeps holding the stdout pipe. To be proposed upstream.
- `event_parse_content.go`: the content-block switch now maps `server_tool_use`
  (server-side tools like webReader, same id/name/input shape as `tool_use`) to
  `EventToolUse` instead of dropping it via the default branch. Without this the
  tool call is invisible and the matching `tool_result` (echoed in an assistant
  message) renders as an empty-name row. To be proposed upstream.

Upstream fix / feature merges: diff against the pinned commit and apply
manually; bump this notice's "Pinned upstream commit" line when syncing.
